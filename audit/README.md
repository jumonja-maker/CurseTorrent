# Воспроизведение аудита CurseTorrent

Полный отчет: [AUDIT-2026-11-22.md](../docs/AUDIT-2026-11-22.md). Проверяемое приложение — исходный коммит `b2aa337a17ebb5351d122de1927eebb5ba484116`, MonoTorrent 3.0.2. Ветка аудита добавляет диагностику и свидетельства, не меняя продуктовые исходники, установщик и основной процесс выпуска.

## Как читать результат

Это диагностические сценарии, а не готовая регрессионная защита. Некоторые завершаются с кодом 0, напечатав **неправильное** поведение приложения. После исправлений нужно заменить такие наблюдения утверждениями о правильном результате и включить их в постоянный CI. Один зеленый прогон не отменяет нестабильный сбой `transitions` в другом прогоне.

Core и файловые проверки используют созданные ими контрольные данные в отдельных каталогах системного Temp. InstallerAudit использует синтетический пакет и не запускает находящийся в нем файл с расширением exe. Установочные ассоциации и ярлыки в этом сценарии не создаются. UI-стенд использует настоящие классы окон и ресурсы приложения с контрольным `ITorrentService`; один длинный magnet проверяет настоящий `InspectAsync`.

## Windows

Нужны Windows x64 и .NET SDK 10. Команды выполняются из корня репозитория. WPF-сценарий требует графической сессии Windows.

```powershell
dotnet run --project tests/CurseTorrent.Tests/CurseTorrent.Tests.csproj -c Release
dotnet run --project audit/network/NetworkAudit.csproj -c Release
dotnet build audit/core/CoreAudit.csproj -c Release
foreach ($mode in @('changed-payload', 'session', 'save-failure', 'transitions', 'metadata-stop')) {
    dotnet run --project audit/core/CoreAudit.csproj -c Release --no-build -- $mode
}
dotnet run --project audit/security/repro/SecurityRepro.csproj -c Release -- existing
dotnet run --project audit/security/repro/SecurityRepro.csproj -c Release -- skipzero
powershell.exe -NoProfile -File audit/security/InstallerAudit.ps1 -RepositoryRoot $PWD.Path
dotnet run --project audit/ui/WindowsUiAudit/WindowsUiAudit.csproj -c Release -- "$env:TEMP\CurseTorrent-ui-audit"
```

`metadata-stop` намеренно использует локальный неотвечающий UDP-трекер. На проверенной версии ожидание паузы заняло около минуты — это зафиксированный дефект F04. Другие сетевые сценарии используют локальных участников и собственный трекер, а не публичную раздачу.

## Сопоставление сценариев

| Проект / режим | Что наблюдает |
| --- | --- |
| `network` | Передачи v1, v2 и hybrid через .torrent и холодный magnet; проверка содержимого |
| `core changed-payload` | Устаревшее восстановление 100% после внешней замены файла |
| `core session` | Восемь вариантов поврежденной или неподдерживаемой структуры JSON и пригодная резервная копия |
| `core save-failure` | Откат состояния при контролируемой ошибке записи |
| `core transitions` | Быстрые recheck / resume / pause; ошибка зависит от расписания выполнения |
| `core metadata-stop` | Время остановки metadata-only magnet и доступность других команд |
| `security existing` | Изменение существующего файла при перепроверке |
| `security skipzero` | Обнуление существующего файла, выбранного как Skip |
| `security InstallerAudit.ps1` | Штатная сохранность посторонних файлов и повтор после прерванной установки |
| `ui WindowsUiAudit` | Сортировка, текст приоритета, сохранение выбора и фокуса, геометрия, снимки, диагностические времена |

Linux подходит для Core, сети и двух файловых сценариев. Отрисовка WPF и проверка блокировки файла установщика выполнены на Windows. Для наблюдения F07 сохранена только описательная запись; специальный некорректный вход не включен.

Не включенный в заключение первоначальный эксперимент `resume` удален из итогового стенда: его гипотеза не подтвердилась, а ожидание определенного состояния приводило к диагностическому таймауту. Пять документированных Core-сценариев после Windows-прогонов не менялись; добавлена справка без аргументов.

## CI и сохраненные результаты

Workflow `.github/workflows/audit.yml` работает в отдельной ветке аудита. Режим `ui_only` при ручном запуске или пометка `[ui-only]` в коммите выполняет только WPF-часть. Обычный запуск выполняет все разделы. Это отдельный диагностический workflow, не изменение обязательных проверок выпуска.

- [Первый Windows-прогон](https://github.com/jumonja-maker/CurseTorrent/actions/runs/44997373944) — подтвержденное исключение start/stop; UI-стенд имел ошибку загрузки ресурсов и не выполнил графические сценарии.
- [Второй полный Windows-прогон](https://github.com/jumonja-maker/CurseTorrent/actions/runs/44997616362) — все разделы завершены; неправильные наблюдения сохранены как дефекты.
- [Итоговый UI-прогон](https://github.com/jumonja-maker/CurseTorrent/actions/runs/44998349506) — корректные снимки и дополнительные проверки отображаемого текста/ширин.

Журналы и итоговые PNG: [evidence](evidence/README.md). Снимки показывают тестовые значения, не скорость пользовательского соединения. Нативная рамка Windows не входит в WPF-render; прозрачные внешние поля не являются дефектом темы.
