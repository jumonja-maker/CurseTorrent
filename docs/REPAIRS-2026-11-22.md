## Дополнительные исправления при работе

### Защита файлов и продолжение

Новые загрузки создают отдельные записи принадлежности файлов, независимые от resume-битовых карт. Windows проверяет идентификатор тома и 128-битный file ID. Это не позволяет случайной замене файла с тем же именем и датой создания получить старое разрешение на запись. Проверка и раздача готового существующего файла остаются доступны без права на изменение.

Для дозагрузки сторонних файлов нужен явный флажок в окне добавления; по умолчанию он выключен. Общее разрешение не распространяется на существующий пропущенный файл ради пограничной части v1. Файл длиннее ожидаемого не обрезается даже при разрешении. При перемещении нельзя заменить существующий target или создать запись принадлежности через отсутствующий источник. Идентификатор проверяется после перемещения.

Если внешний завершённый файл имеет суффикс `.!mt`, проверка сохраняет его имя. Отказ от перемещения возвращается в DiskManager, и логический путь не меняется без физического перемещения. Проверка включает восстановление, Resume и настоящую передачу данных новому получателю из такого файла.

### Метаданные, состояние и нагрузка

Размер локального `.torrent` ограничивается до выделения буфера. Рекламируемый размер magnet-метаданных проверяется до приведения к `int` и создания массива. Одновременно метаданные получают не более четырёх задач. Завершённые фоновые задачи удаляются из набора наблюдения, не удерживая большие результаты.

Добавлены ограничения длины компонента имени, зарезервированные Windows-имена COM/LPT с `¹²³` и коллизии «файл/папка» без учёта регистра. Предел сессии 32 МиБ действует и на запись: нельзя сохранить документ, который клиент затем сам откажется читать. Ошибка открытия файлового потока корректно освобождает блокировку и счётчик открытых файлов.

### Интерфейс и установщик

Горизонтальные scroll-команды больше не вызывают вертикальную прокрутку. Добавлены видимый клавиатурный фокус и переключение ресурсов на системную контрастную палитру. Длинные имена, ошибки и многочисленные startup warnings сокращаются в native MessageBox; полный диагностический текст сохраняется в журнале. Подпись автоматического порта и отображение версии приведены к фактическому состоянию.

Манифест установщика версии 2 содержит SHA-256. Обновление не перезаписывает неизвестные или изменённые программные файлы; удаление сохраняет их. Переход со старого манифеста создаёт отдельную резервную папку. Это не подпись пакета и не защита от изменения служебных файлов другим локальным процессом того же пользователя.

## Проверки сборки

Локально прошли исходные 47 интеграционных assertions, 47 проверок файлов/декодера, 173 регрессионных assertions и все шесть передач v1/v2/hybrid через torrent/magnet. Точный итог регрессионного набора, Windows UI и установщика фиксируется в журнале завершённого workflow и приложенных к выпуску файлах; публикация выпуска зависит от успешного завершения всех обязательных этапов.

Источники проверок и воспроизводимые команды — [VALIDATION.md](VALIDATION.md). UI runner создаёт JSON результатов и одиннадцать PNG настоящих WPF окон с синтетическими данными. Сетевые проверки используют реальные loopback соединения, временные файлы и сравнение SHA-256, без внешних торрент-сетей.

## Изменения поведения, заметные пользователю

- После запуска процесса восстановленные данные проходят проверку. Большие раздачи могут некоторое время показывать «Проверка», даже если ранее были на паузе; после проверки пауза сохраняется.
- Неизменённые ранее проверенные файлы могут продолжаться без полного хеширования после паузы в том же процессе. После реальной дозагрузки или сомнений в состоянии применяется полная проверка.
- При переходе с 0.1.0 старым незавершённым файлам может потребоваться явное разрешение: удалить только задачу из списка, добавить её в ту же папку и включить дозагрузку существующих файлов. Удаление из списка сохраняет данные.
- Слишком длинный существующий файл не обрезается; выберите другую папку или перенесите файл вручную.
- Исправный чужой `.!mt` может раздаваться под прежним именем. Проверка сама его не переименует.
- Для обновления установленных ранних preview сохраняется отдельная резервная папка. Удалять её следует после проверки новой версии.

## Что эти проверки не подтверждают

Публичные трекеры, DHT, роутер, VPN и брандмауэр конкретного пользователя не проверяются локальными передачами. WPF runner не заменяет длительную работу на пользовательском Windows 11, смену мониторов/DPI, Narrator/NVDA и системный трей. Проверка системной палитры не переключает глобальную настройку высокой контрастности Windows. Устойчивость к любой аппаратной ошибке диска не обещается. Preview остаётся без цифровой подписи издателя.
