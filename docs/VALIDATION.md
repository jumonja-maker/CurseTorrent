# Проверки CurseTorrent

Этот файл описывает процесс проверки. Конкретный результат определяется журналом соответствующего коммита и сборки, а не наличием workflow.

## Автоматический процесс

Workflow [build.yml](../.github/workflows/build.yml) запускается при изменении `main`, веток `fix/**`, pull request и ручном запуске:

1. Восстанавливает зафиксированные зависимости и выполняет исходные, регрессионные, файловые и сетевые проверки на Linux.
2. Разбирает PowerShell-скрипты штатным парсером на Windows.
3. Выполняет регрессионные, файловые и сетевые проверки на Windows.
4. Запускает отдельный нативный WPF runner с настоящими окнами, ресурсами и привязками приложения; сохраняет JSON assertions и PNG.
5. Повторяет исходные интеграционные проверки на Windows, собирает WPF-приложение и автономный пакет `win-x64`.
6. Распаковывает готовый ZIP и запускает `.exe` с `--smoke-test`, ожидая успешного завершения максимум 45 секунд. Сохраняет PNG настоящего окна с пустым сеансом.
7. В Windows PowerShell 5.1 проверяет установку, обновление, откат при ошибках и прерывании, миграцию старого манифеста и удаление с сохранением контрольных пользовательских файлов.
8. Только после успешных проверок и push в `main` публикует предварительную сборку, ZIP, SHA-256, PNG, JSON интерфейсных проверок и журналы. Для `fix/**` и pull request публикации нет.

Workflow не загружает GitHub Actions Artifacts. Выпуск сначала создаётся черновиком и становится видимым после загрузки всех файлов. Каждая попытка получает отдельный тег.

## Наборы проверок

| Проект | Что подтверждает |
| --- | --- |
| `CurseTorrent.Tests` | Реальная передача и раздача, приоритеты, пауза, восстановление, сохранение отдачи, коллизии путей; SHA-256 контрольных файлов |
| `CurseTorrent.RegressionTests` | Изменение содержимого между запусками, смысловое повреждение/будущие версии сессии, резервные копии, отмена magnet, гонки состояния |
| `CurseTorrent.FileSafetyTests` | Неизменность существующих файлов, нулевые/пропущенные файлы, явная дозагрузка, замена файла с тем же именем, малые тестовые квоты декодера, ограничения имён Windows |
| `CurseTorrent.CompatibilityTests/NetworkAudit.csproj` | Шесть реальных передач: v1, v2, hybrid через `.torrent` и magnet |
| `CurseTorrent.UiTests` | Сортировка и live updates, четыре приоритета и команды, фокус, горизонтальная прокрутка, границы рабочей области, длинные строки/ошибки и короткие окна, разрешение существующих файлов, системная палитра |
| `scripts/test-install.ps1` | Ошибки копирования и блокировки файлов, rollback/recovery, неизвестные/изменённые файлы, старый манифест, границы путей, сохранность данных после удаления |

Для любого консольного проекта:

```shell
dotnet restore <project.csproj> --locked-mode --disable-parallel -m:1
dotnet build <project.csproj> -c Release --no-restore -m:1
dotnet run --project <project.csproj> -c Release --no-build --no-restore
```

Путь WPF runner и описание снимков: [tests/CurseTorrent.UiTests/README.md](../tests/CurseTorrent.UiTests/README.md). Сценарии используют временные каталоги и локальные сетевые адреса, не пользовательские загрузки. Проверки декодера используют небольшие обычные структуры с намеренно малыми тестовыми квотами; аварийные образцы не распространяются.

## Проверка вручную на Windows 11

| Сценарий | Критерий |
| --- | --- |
| Первый запуск, масштаб 100/125/150% | Элементы читаются, доступны и не перекрываются |
| `.torrent` | Правильные имя, размер и файлы; загрузка в выбранную папку |
| Magnet | Получаются метаданные при наличии пиров, затем доступны файлы |
| Пауза при загрузке и получении метаданных | Передача останавливается, продолжение работает |
| Выбор файлов | Пропущенные файлы не скачиваются целиком; пограничные части могут требоваться движку для проверки |
| Перезапуск | Список, приоритеты и паузы сохраняются; активные задачи следуют настройке автопродолжения |
| Битый `.torrent`, недоступная папка | Понятная ошибка, остальные задачи продолжают работу |
| Потеря и восстановление сети | Интерфейс остаётся отзывчивым, загрузка может продолжиться |
| Перепроверка | Повреждённые части обнаруживаются и могут быть скачаны заново |
| Ограничение скорости | При достаточно быстрых пирах длительная скорость близка к установленному пределу |
| Трей и ассоциации | Окно возвращается, выход завершает процесс, новый файл передаётся существующему экземпляру |
| Обновление и удаление | Загрузки и сохранённый сеанс остаются |

Для ручной сетевой проверки подходит официальная раздача Linux-дистрибутива. Зафиксируйте ссылку, время, размер, число пиров и результат; не включайте личные пути в публичный отчёт.

## Границы автопроверок

Локальная передача между двумя BitTorrent-движками подтверждает передачу и целостность контрольных данных. Она не проверяет внешние трекеры, DHT в конкретной сети, роутер, VPN и брандмауэр.

WPF-проверки подтверждают загрузку XAML, реальные привязки и команды, размеры и отрисовку окон при DPI/рабочей области runner. Проверка системной палитры вызывает production theme code, но не переключает глобальную настройку высокой контрастности. Не проверены на реальном рабочем столе все масштабы и переходы между мониторами, Narrator/NVDA, трей и длительная работа. Синтетические скорости на снимках не являются сетевым бенчмарком.
