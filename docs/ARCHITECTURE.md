# Устройство проекта

## Компоненты

`CurseTorrent.App` — нативный WPF-интерфейс Windows. Он получает снимки `TorrentSnapshot` раз в секунду и вызывает асинхронные команды через `ITorrentService`. Здесь находятся диалоги, трей, регистрация обработчиков Windows и передача аргументов уже запущенному экземпляру через ограниченный именованный канал текущего пользователя. Рабочие потоки движка не меняют элементы интерфейса.

`CurseTorrent.Core` — независимое от WPF ядро .NET 10. Оно владеет движком, сериализует изменения списка задач, сохраняет сессию, управляет проверкой данных, приоритетами и разрешениями на запись. Длительная отмена получения метаданных выполняется вне общей блокировки пользовательских команд.

`vendor/MonoTorrent` — исходники MonoTorrent 3.0.2, закреплённые на upstream-коммите `e78faebd0aec117146cffccaaea987ab0629eec0`, с локальными исправлениями IO, жизненного цикла и разбора метаданных. Сохраняются одиннадцать исходных сборок и лицензии. Происхождение и изменения перечислены в [README зависимости](../vendor/MonoTorrent/README.md). Возвращать обычный пакет 3.0.2 без переноса исправлений нельзя.

## Метаданные и пути

Входной `.torrent` читается через ограниченный поток: размер от 1 байта до 16 МиБ, точное чтение и проверка изменения длины. Декодеры bencode имеют общий бюджет глубины, числа объектов и объёма строк; арифметика чисел и длин проверяет переполнение. Для magnet размер метаданных ограничивается до выделения буфера. Одновременно получают метаданные не более четырёх задач; отмена ожидающей задачи не создаёт скрытый менеджер движка.

Метаданные проверяются до обычной загрузки: относительные имена, ограничения Windows, зарезервированные имена, совпадения без учёта регистра, пересечения «файл/папка». Резервируются готовые пути и варианты `.!mt`. Ядро не допускает пересечения задач и служебных данных приложения, проверяет reparse points при обращении к содержимому.

Проверенный `.torrent` копируется в служебный каталог. Удаление оригинала не мешает восстановлению. Неизвестный magnet сначала получает метаданные, затем проходит те же проверки и превращается в обычную задачу.

## Чтение, запись и принадлежность файлов

Исправленный `DiskWriter` читает существующие файлы без создания, обрезания и изменения длины. Создание нулевых файлов проходит через `IPieceWriter` и учитывает `DoNotDownload`. Проверка хешей не переименовывает содержимое. Отказ от физического перемещения передаётся через `TryMoveAsync`, поэтому движок сохраняет фактический путь файла.

`GuardedPieceWriter` проверяет зарезервированный путь при IO, а перед записью — `PayloadOwnership`. Новые файлы создаются через `CreateNew`. Для созданного или явно принятого файла сохраняется отдельная запись принадлежности в `payload-ownership`. Она включает путь, ID раздачи и идентификатор файла ОС; Windows использует volume ID и 128-битный file ID, тестовый Linux — устройство, inode и время рождения из `statx`. Обычная запись не меняет идентификатор; при выключенном разрешении `AllowExistingFiles` замена файла по тому же пути не получает прежнее разрешение автоматически.

Сторонние существующие данные разрешено читать и раздавать без принятия во владение. Запись требует флажка `AllowExistingFiles` из окна добавления; это разрешение сохраняется в сессии. Файлы длиннее ожидаемого не обрезаются даже при разрешении. Общее разрешение не принимает существующий пропущенный файл ради пограничной части v1. Части в собственных пропущенных файлах могут быть необходимы движку для проверки соседних выбранных данных.

Завершение собственной загрузки может переименовать `.!mt`, если подтверждён идентификатор источника, путь назначения свободен и идентификатор после перемещения совпадает. Чужой готовый `.!mt` остаётся под прежним именем и может раздаваться оттуда. Потеря записи принадлежности требует явного повторного разрешения. Эта защита предотвращает случайную перезапись; она не является границей безопасности против другого локального процесса, который может менять файлы и служебные данные того же пользователя.

## Сессия и жизненный цикл

`session.json` сохраняет источники, папки, приоритеты, разрешение использовать существующие файлы, намерение продолжать загрузку и статистику отдачи. `settings.json` содержит настройки. Синтаксическая и смысловая проверка документа выполняется до принятия его или ротации резервной копии. Повреждённый основной файл сохраняется отдельно; исправная `.bak` восстанавливает основной файл без перезаписи самой резервной копии повреждёнными данными. Неизвестная будущая версия не перезаписывается. Предел состояния — 32 МиБ как для чтения, так и для записи.

После запуска процесса все восстановленные задачи с метаданными проходят полную проверку содержимого. До неё кешированный процент не считается доказательством целостности. Проверка идёт в фоне; намерение паузы сохраняется. Fast-resume автоматически не загружается. Ручная перепроверка всегда читает содержимое заново. В том же процессе возможен быстрый Pause/Resume для данных, чей размер, время записи и native file ID совпадают с эталоном, снятым вокруг успешного полного хеширования, до/после Stop и перед Resume; полученные после эталона payload-байты исключают этот быстрый путь. В v1 учитываются также соседние файлы, разделяющие выбранные граничные части. При отсутствии файлов, ошибке чтения атрибутов или изменении применяется полная проверка.

Пауза реализована через остановку с сохранением, поскольку штатная пауза движка не охватывает все стадии. `StopAsync` сбрасывает счётчики MonoTorrent, поэтому наблюдавшаяся отдача переносится в накопительный счётчик. Задача хеширования отделена от обработчика завершения: остановка ждёт задачу движка без повторного захвата блокировки команд. Поколение операции и проверка текущего режима не позволяют старому продолжению после `await` заменить новое состояние.

Остановка скрытого magnet-менеджера ограничивает завершающий tracker announce двумя секундами; это не общий предел для произвольных задержек ОС/диска. Продолжение ждёт завершения предыдущей очистки, чтобы не создать дубликат. Завершённые фоновые задачи удаляются из набора наблюдения, включая полученные буферы метаданных. Удаление из списка завершает работу задачи и сохраняет пользовательские файлы.

## Установка и выпуск

Установщик готовит проверенный пакет во временной папке, ведёт журнал операции и сохраняет предыдущие файлы для отката. Манифест версии 2 содержит SHA-256. Неизвестный или изменённый файл не перезаписывается при обновлении и не удаляется при деинсталляции. Первая миграция старого манифеста сохраняет отдельную резервную папку. Детали: [INSTALLER-RECOVERY.md](INSTALLER-RECOVERY.md).

NuGet-зависимости закреплены lock-файлами. Workflow последовательно выполняет интеграционные и регрессионные проверки на Linux и Windows, WPF-проверки, публикацию автономного `win-x64`, запуск готового `.exe` и установку/обновление/откат/удаление. Предварительный выпуск создаётся только после этих этапов. Объём и пределы проверки описаны в [VALIDATION.md](VALIDATION.md).
