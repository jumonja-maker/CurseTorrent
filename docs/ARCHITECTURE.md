# Устройство проекта

## Границы компонентов

`CurseTorrent.App` — нативный WPF-интерфейс Windows. Он получает неизменяемые снимки `TorrentSnapshot` раз в секунду и вызывает асинхронные команды через `ITorrentService`. В нём находятся диалоги, трей, регистрация обработчиков Windows и передача аргументов уже запущенному экземпляру через ограниченный именованный канал текущего пользователя.

`CurseTorrent.Core` — независимое от WPF ядро на .NET 10. Оно владеет MonoTorrent 3.0.2, сериализует пользовательские команды, сохраняет сессию и управляет приоритетами. Рабочие потоки движка не обновляют элементы интерфейса.

`CurseTorrent.Tests` — консольные интеграционные проверки с настоящими файлами, сидером, получателями и локальным UDP-трекером. Они сверяют SHA-256 и не обращаются к публичным торрент-сетям. `offlineMode` отключает DHT, локальное обнаружение пиров и проброс портов; это режим тестов.

## Добавление и сохранение

`.torrent` проверяется и копируется в служебную папку до запуска. Удаление оригинала не влияет на восстановление. Неизвестная magnet-ссылка сначала проходит `DownloadMetadataAsync`; после получения метаданные проверяются, сохраняются как `.torrent`, и только затем создаётся обычная загрузка. Это принципиально для MonoTorrent 3.0.2: создание нулевых файлов в `StartingMode` обходит `IPieceWriter`.

`GuardedPieceWriter` проверяет принадлежность пути перед чтением, записью, проверкой наличия и перемещением. Резервируются как готовые имена, так и `.!mt`, включая пересечения внутри одной раздачи. Служебные файлы приложения защищены от назначения их в качестве загружаемых файлов. Закрытие и сброс уже открытых файлов остаются доступны для корректного завершения.

`session.json` сохраняет источники, папки, приоритеты, намерение продолжать загрузку и статистику отдачи. `settings.json` содержит настройки. Запись идёт во временный файл с заменой и резервной копией; повреждённые данные сохраняются отдельно перед восстановлением. Ошибка одной записи не прерывает восстановление остальных. Fast-resume ведёт движок в режиме `Accurate`; незавершённое аварийное отключение может потребовать проверки данных.

## Особенности жизненного цикла

- Пауза реализована через остановку с сохранением; штатный `PauseAsync` движка не охватывает все стадии.
- `StopAsync` сбрасывает счётчики MonoTorrent, поэтому наблюдавшаяся отдача переносится в накопительный счётчик.
- Перед ручной перепроверкой вызывается `SetNeedsHashCheckAsync`, чтобы прерванная проверка не сохраняла несовместимые битовые поля fast-resume.
- Необработанная задача хеширования отделена от обработчика её завершения. Остановка ждёт именно задачу движка, не захватывая повторно блокировку команд.
- Удаление задачи прекращает передачу и убирает её из сессии; данные пользователя остаются на диске.

## Проверка и выпуск

Версии NuGet закреплены lock-файлами. Сначала проходят интеграционные проверки на Linux и Windows, затем публикация `win-x64`, запуск готового WPF `.exe`, проверка привязок и отрисовки диалогов, установка/обновление/удаление с сохранением контрольного файла. Предварительный выпуск создаётся только после этих этапов. Пределы автоматической проверки описаны в [VALIDATION.md](VALIDATION.md).
